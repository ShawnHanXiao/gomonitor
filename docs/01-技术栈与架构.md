# GoMonitor 技术栈与架构

## 1. 技术选型

| 方案 | 结论 |
| --- | --- |
| 运行时 | .NET 9，本机已安装 `dotnet 9.0.311` |
| UI | WPF (XAML)，Windows 原生窗口 |
| 托盘 | `System.Windows.Forms.NotifyIcon`，随 .NET 自带，无需第三方包 |
| 语言 | C# |
| JSON | `System.Text.Json` |
| 测试 | xUnit |
| 发布 | `dotnet publish` 自包含单文件 exe |

备选方案对比：

- Electron + TS：Web 界面开发快，但体积、内存占用大，对常驻托盘工具不划算。
- Tauri 2：产物轻，但本机未安装 Rust/cargo，需要额外安装工具链。
- .NET 9 WPF：本机已有 .NET，原生托盘体验好，依赖最少，最贴合单机常驻工具。

## 3. 模块职责

### App.xaml.cs

- 启动时做单实例检测。
- 加载设置、创建托盘图标、启动轮询定时器。
- 负责窗口生命周期：面板和设置窗口都只隐藏，不退出。

### AuthKeyProvider

- 优先读取设置中的 API Key 覆盖。
- 否则读取 `C:\Users\shawn\.local\share\opencode\auth.json`：

```json
{
  "opencode-go": {
    "type": "...",
    "key": "..."
  }
}
```

- 不记录、不输出 key 明文。

### OpenCodeUsageService

- 每 N 秒调用一次用量接口。
- 超时 10 秒，失败时保留上次数据并标记错误状态。
- 输出 `UsageSnapshot`：

```csharp
public sealed record UsageSnapshot(
    double? RollingPercent,
    double? WeeklyPercent,
    double? MonthlyPercent,
    DateTimeOffset? RollingResetsAt,
    DateTimeOffset? WeeklyResetsAt,
    DateTimeOffset? MonthlyResetsAt,
    DateTimeOffset FetchedAt,
    bool HasError,
    string? ErrorMessage);
```

### TrayIconController

- 持有 `NotifyIcon`，根据 `UsageSnapshot` 生成图标颜色和 tooltip。
- 左键点击切换 MonitorWindow，右键打开 ContextMenuStrip。
- 图标用 `System.Drawing` 绘制：固定尺寸圆形底 + 状态色填充。

### MonitorWindow

- 无边框弹出面板，`AllowsTransparency=true`，`ShowInTaskbar=false`。
- 定位在工作区右下角托盘附近。
- 失焦时关闭。

### SettingsWindow

- 普通 WPF 窗口，读写 `AppSettings`。

## 4. API 契约

请求：

```http
GET https://opencode.ai/zen/go/v1/usage
Authorization: Bearer <key>
Accept: application/json
```

响应结构（关键字段）：

```json
{
  "usage": {
    "rolling": { "status": "ok", "percent": 4, "resetsAt": "2026-01-01T00:00:00Z" },
    "weekly":  { "status": "ok", "percent": 4, "resetsAt": "2026-01-01T00:00:00Z" },
    "monthly": { "status": "ok", "percent": 2, "resetsAt": "2026-01-01T00:00:00Z" }
  }
}
```

解析规则：

- `status != "ok"` 或 `percent` 缺失时，该窗口期视为不可用。
- 百分比按 `double` 解析，保留一位小数展示。
- `resetsAt` 按 ISO 8601 解析，展示为本地时间倒计时。
- 非 200 响应、网络异常、JSON 异常统一进入错误状态。

## 5. 设置与持久化

配置文件位置：`%APPDATA%\GoMonitor\settings.json`

```json
{
  "apiKeyOverride": "",
  "pollIntervalSeconds": 60,
  "startWithWindows": true
}
```

- `apiKeyOverride` 留空时使用 `auth.json`。
- 开机自启写入：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\GoMonitor`。
- 关闭开关时删除该注册表值。

## 6. 阈值与颜色

```text
percent < 60            -> #3FB950 (green)
60 <= percent < 80      -> #E3B341 (yellow)
80 <= percent < 95      -> #F0883E (orange)
95 <= percent           -> #E5484D (red)
error / no key           -> #8B949E (gray)
```

## 7. 构建与发布

```powershell
cd D:\code\gomonitor
dotnet build GoMonitor.sln
dotnet test GoMonitor.sln
dotnet publish src/GoMonitor/GoMonitor.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -o publish
```

产物：`publish/GoMonitor.exe`（约 74 MB 单文件，含 .NET 运行时可独立运行）。

> 若环境无法访问 nuget.org，先将 `Microsoft.NETCore.App.Runtime.win-x64` 与
> `Microsoft.WindowsDesktop.App.Runtime.win-x64`（版本与目标 runtime 一致）放入本地文件夹，
> 再以 `dotnet restore -r win-x64 --source <folder> -p:NuGetAudit=false` 还原，之后
> 上面的 publish（追加 `--no-restore`）即可离线完成。当前机器已缓存这些包。

## 8. 测试计划

- 单元测试：
  - 用量 JSON 解析，覆盖正常、缺字段、错误 status。
  - 阈值到颜色的映射边界值（59.9 / 60 / 79.9 / 80 / 94.9 / 95）。
  - 设置读写与默认值。
- 手动冒烟：
  - 启动后托盘图标出现，tooltip 包含三个百分比。
  - 左键弹出面板、失焦关闭。
  - 设置窗口保存后立即生效。
  - 开机自启开关正确写删注册表。

## 9. 安全注意事项

- API Key 只在内存中使用，不写入日志。
- 设置文件中的覆盖 key 为明文，与 `auth.json` 的明文级别一致。
- 不在 UI 中完整回显 key，只显示最后 4 位用于确认。
