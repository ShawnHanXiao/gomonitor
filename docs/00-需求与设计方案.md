# GoMonitor 需求与设计方案

## 1. 背景

用户通过 Trae、ChatGPT/Codex 等工具调用 OpenCode Go 的 API 进行开发，但 OpenCode 网页端查看用量信息不完整、操作繁琐。需要一个本地 Windows 工具常驻系统托盘，让 5 小时/每周/每月用量百分比一眼可见。

本项目名暂定 **GoMonitor**，代码位于 `D:\code\gomonitor`。

## 2. 调研结论

### 2.1 官方用量接口

OpenCode Go 的 API Key 只能访问一个官方用量接口：

```http
GET https://opencode.ai/zen/go/v1/usage
Authorization: Bearer <opencode-go-key>
```

响应只包含 5 小时（rolling）、每周（weekly）、每月（monthly）三个百分比和对应的重置时间：

```json
{
  "usage": {
    "rolling": { "status": "ok", "percent": 4, "resetsAt": "..." },
    "weekly":  { "status": "ok", "percent": 4, "resetsAt": "..." },
    "monthly": { "status": "ok", "percent": 2, "resetsAt": "..." }
  }
}
```

该接口不返回输入/输出 token、缓存命中、请求次数、具体模型等明细。

### 2.2 模型明细为何不可行

页面上的模型调用明细来自登录态的网页控制台查询数据库，API Key 无对应权限。唯一可行路径是让本机代理截获 Trae/Codex 到 `https://opencode.ai/zen/go/v1/*` 的请求和响应（例如 CC Switch 本地代理，或新建一个本地转发代理），并解析响应中的 usage 字段。

与用户确认后，**v1 不做代理改造**，采用低配方案：托盘图标 + hover + 弹出面板只显示官方接口提供的三个用量百分比。

### 2.3 已知账号与额度

- 本机认证文件：`C:\Users\shawn\.local\share\opencode\auth.json`，其中 `opencode-go` 对象包含 `type` 与 `key`。
- OpenCode Go 官方额度：5 小时 `$12`、每周 `$30`、每月 `$60`。
- 官方控制台入口：<https://opencode.ai/auth>。

## 3. 决策记录

| 决策 | 结论 |
| --- | --- |
| 监控账户 | v1 只监控本机 `auth.json` 中的 `opencode-go` 账号 |
| 明细数据 | 不做代理、不解析模型明细，v1 只显示官方用量百分比 |
| 技术栈 | .NET 9 WPF + C#，Windows 原生托盘 |
| 弹出面板 | 无边框紧凑面板，点击外部关闭，固定深色 |
| 设置入口 | 极简设置窗口，由托盘右键菜单进入 |
| 认证方式 | 默认自动读取 `auth.json`，设置窗口允许手动覆盖 key |
| 刷新频率 | 默认每 60 秒轮询一次，可在设置中修改 |
| 启动行为 | 支持开机自启（写 HKCU Run），关闭窗口最小化到托盘 |
| 提醒 | v1 不做系统通知，只用图标颜色表达状态 |
| 发布形态 | 单文件绿色 exe，不做安装器和自动更新 |

## 4. 功能需求

### 4.1 托盘图标

- 常驻系统托盘，图标颜色代表 5 小时用量百分比：
  - `< 60%`：绿色
  - `>= 60% 且 < 80%`：黄色
  - `>= 80% 且 < 95%`：橙色
  - `>= 95%`：红色
  - 未获取到数据（无 key、网络失败、解析失败）：灰色
- 鼠标 hover 提示一行紧凑文本，例如 `5h 13% | Week 12% | Month 8%`。
- 左键单击：切换显示用量面板。
- 右键菜单：`Open Monitor`、`Refresh Now`、`Settings`、`Exit`。

### 4.2 用量面板（左键弹出）

- 无边框、深色、紧凑的小窗口，靠近托盘区域弹出，点击外部或失焦自动关闭。
- 内容：
  - 三行用量：`5h`、`Week`、`Month`，每行显示百分比、进度条、重置倒计时。
  - 状态色与托盘规则一致。
  - `Last updated HH:mm:ss`。
  - `Refresh` 按钮，立即发起一次轮询。
  - `Open Console` 链接，打开官方控制台 <https://opencode.ai/auth>。
  - 底部 `Settings` 按钮，打开设置窗口。
- 异常状态下显示错误摘要，而不是空白或假数据。

### 4.3 设置窗口

- 由托盘右键菜单进入。
- 字段：
  - API Key 覆盖（可留空，留空时使用 `auth.json`）。
  - 轮询间隔（秒，默认 60，可选 15/30/60/120）。
  - 开机自启开关。
  - 保存/取消。
- 设置持久化到 `%APPDATA%\GoMonitor\settings.json`。

### 4.4 进程行为

- 单实例运行，重复启动时激活已有实例。
- 关闭面板/设置窗口只隐藏，不退出程序；只有右键菜单 `Exit` 退出。
- 开机自启以 `--minimized` 参数启动，只驻留托盘。

## 5. 数据流

```text
Trae / ChatGPT / Codex 客户端
        |
        | 现有路径，不作改动
        v
OpenCode Go API (opencode.ai/zen/go/v1/*)
        ^
        |
        | HTTPS GET /usage + Bearer key
        |
GoMonitor (托盘常驻)
  auth.json / settings.json -> 用量轮询 -> 图标颜色 / hover / 弹出面板
```

## 6. UI 设计原则

界面使用英文，遵循 `design-taste-frontend-v1` 中可迁移到 WPF 的原则：

- 深色中性底色，单一状态色只用于用量/状态，不使用 AI 紫或渐变装饰。
- 数字使用等宽字体，密度紧凑，信息优先，无多余卡片嵌套。
- 面板宽度约 340px，三行用量直接以分隔线分组，不套多层卡片。
- 按钮图标使用清晰的矢量符号，避免 emoji。
- 必须覆盖加载中、正常、错误三种状态。

## 7. 边界与异常

- 本机 `auth.json` 不存在且设置中无 key：图标灰色，hover 提示 `No API key`，面板提示打开设置。
- HTTP 请求失败：保留上一次成功数据，但状态按错误处理；图标灰色，面板显示错误信息。
- 接口返回缺少字段：按对应窗口期不可用处理，不显示伪造百分比。
- 重置时间按本地时区展示倒计时。

## 8. 暂不实现（v2 候选）

- 本地代理截获流量，展示每日/模型级 token、缓存、请求次数明细。
- 多账号切换、历史趋势图、阈值通知。
- 安装器、自动更新、多语言切换。
